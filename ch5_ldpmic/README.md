# Chapter 5 — LDP-MIC: federated correlation-aware differential privacy enforced by the client

Code, configurations and recorded runs behind Chapter 5 of the dissertation. Every number in the chapter's tables
and figures comes from a recorded run in `results/` (configuration, seed, code commit, timing and environment in
the run's JSON), and every table and figure is generated by a script; nothing is typed by hand.

**Code commit.** The follow-up runs (local score release, rescaled rerun of Experiment 1, DP-SGD diagnosis,
group-wise sensitivity) were fixed in their settings and launched at commit `a342959`
(`a3429596b1390fef5c7e28be38114de4b5d306fc`) of the development repository, which is not public; this directory
is a snapshot of that code without its history. Each run records the exact commit it ran at (`git_commit`;
a `-dirty` suffix means the working tree had uncommitted changes, such as the run log, when the run started).

## Quick check (CPU, offline, a few minutes)

```bash
cd ch5_ldpmic
make setup            # Python 3.13 venv with ../requirements.txt (CPU-only PyTorch wheel)
. .venv/bin/activate
make check            # unit tests + every table and figure of the chapter regenerated into thesis_tex/
```

`make check` needs no dataset: it reads the committed summaries (`results/summary/`) and run records
(`results/raw/`, `results/ch5/`). Re-running experiments needs the datasets (`make data`, below).

## Re-running experiments

```bash
make data                                   # download + verify the datasets (URLs and SHA-256 in data/MANIFEST.md)
python scripts/run_sweep.py configs/<name>.yaml --eps <e> --seeds <s>    # one run; completed runs are skipped
python scripts/run_attacks.py attribute --configs configs/adult_occ_v7_sel_mi_k10.yaml --attributes sex race
make aggregate                              # results/raw -> results/summary
make followup central                       # follow-up and Experiment 5 reports
make outputs                                # all tables and figures of the chapter
```

The command of every recorded run is stored in its JSON (`command`), and its configuration in `config`.
Compute: CPU only (4 cores); the image sweeps take tens of minutes per run with DP-SGD.

## Layout

```
ldpmic/            privacy.py (analytic Gaussian mechanism, RDP accountant), scores.py, allocation.py, perturb.py,
                   dpsgd.py, fl.py (FedAvg), models.py, metrics.py, pipeline.py, data/ (loaders, partitions), attacks/
configs/           one YAML per experiment; a run = config + seed (+ eps)
scripts/           run_sweep.py, run_attacks.py, run_central.py, aggregate*.py, make_figures.py, make_tables.py,
                   gen_ch5.py (+ gen_ch5_followup.py), ch5d3_gen_configs.py, ch5d3_report.py, majority_rates.py, download_data.py
results/raw/       per-run CSV (per round) + JSON (provenance and final metrics) (+ *_vectors.npz, *_norms.npz)
results/summary/   aggregated CSVs used by the tables and figures
results/ch5/       draft3/ (follow-up runs and reports), central/ (Experiment 5)
figures/, tables/, thesis_tex/   generated outputs
data/              RANGES.md (public feature ranges), MANIFEST.md (sources and SHA-256); datasets are downloaded, not included
tests/             pytest
```

Datasets: UCI Adult and Bank Marketing (UCI Machine Learning Repository), MNIST and Fashion-MNIST (via
torchvision); they are not redistributed here and are downloaded from the sources in `data/MANIFEST.md`.
The robustness evaluation cited in the chapter's discussion (commit `65fd7b6`) belongs to an earlier code base and is
not part of this directory.
