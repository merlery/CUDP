## Part B. Experiment 1 with stable training

### B.1 Diagnosis (stored runs, no new training)

**What "failed numerically" means in the code.**  A run is flagged `diverged` by `scripts/run_sweep.py` when a
model parameter or the training loss of any round is not finite; the run still completes and its final metrics
are those of the model with non-finite parameters, whose prediction is class 0 for every test record (argmax of
non-finite logits).  For stored runs that predate the flag it is recomputed from the per-round file (non-finite
training loss).  A second, different outcome is counted separately below: a run with finite losses whose final
model predicts one class for the whole test set.

**Are the privatized inputs rescaled or standardized?**  No.  In the stored Experiment 1 runs the released
coordinates pass only through the public affine map of [a_j, b_j] to [0, 1] (`ldata.public_scaler`); there is no
standardization, no clipping of the released values and no division by the noise scale.  The first table gives the
mean absolute network input per budget next to that of the clean inputs.

**Adult at eps 1, 2, 5.**  The second table gives the confusion matrix of the final model per seed, recovered
exactly from the stored accuracy, balanced accuracy and test class counts (the stored runs did not save
predictions), together with the number of rounds with a non-finite loss and the largest round-mean update norm.

## Part F. Group-wise sensitivity (optional)

Uniform release on Adult calibrated to the group-wise l2 sensitivity, squared sensitivity n_numeric +
2 n_categorical in units of the scaled ranges, instead of d.  Proof sketch: after the public affine map each
numeric coordinate lies in [0, 1], so replacing a record changes it by at most 1 and the numeric block contributes
at most n_numeric to the squared l2 distance; each categorical attribute is a one-hot block with exactly one entry
equal to 1, so two records differ in at most two entries of the block, each by 1, and the block contributes at most
2; summing over blocks, ||x - x'||_2^2 <= n_numeric + 2 n_categorical, and the Gaussian mechanism with
sigma = c(eps, delta) * sqrt(n_numeric + 2 n_categorical) per scaled coordinate is (eps, delta)-DP for the
record.  The bound requires every record to be a valid one-hot encoding; coordinate-wise clipping alone does not
enforce that, so a client must validate its records before the release (true by construction for the loader's
records).  The stored uniform release at eps 10 has no update clipping; a reference run with the protocol of the
other budgets was added and both are shown.

## Deviations

1. Order of the parts: one job queue in the order A, B, C, F on 4 parallel workers; D, E and the diagnostics of
   B.1 and C.1 were computed from stored files while the runs of A and B were in progress.  All decision-log plan
   entries (D65-D70) were written together before the first run and cite the same commit.
2. Part A, local mode: each client clips its noisy score vector to [0, 1] before the average (the mechanism as
   specified in the repository); the task text does not say so.  The overlap without that clipping is reported as a
   diagnostic.
3. Parts A and D: the code's sensitivity bound is not the task's Delta_FG formula (Part D).  All runs use the
   code's bound; the task formula's values are printed next to it and no run was made with it.
4. Part B.1: the stored runs saved no predictions; the Adult confusion matrices are recovered from the stored
   accuracy and balanced accuracy (exact for a binary task; integer check in the script).  The mean absolute input
   of the stored runs is recomputed by re-running the release without training (seed 0).
5. Part B.2: s_j = 0.25 for all features; the image-data oracle allocation exists in the stored Experiment 1 only
   at eps 1 and 5 and was rerun only there.  The lr / 10 repeat was conditional on a run failing numerically.
6. Part C.1: per-update norms and the fraction of updates clipped do not exist for the stored runs (replaced by the
   share of rounds whose mean norm exceeds C).  C.2: the rule reads training-side update norms of one seed; it uses
   no test metric but is not data-independent.  The eps = 1 cells of the per-budget version are the stored runs.
7. Part F: a uniform reference run at eps 10 under the update-clipping protocol was added (not in the task).
8. The container restarted during Part C; runs in progress were lost and started again from the beginning (completed
   runs were kept and skipped), so the new runs carry several code commits.  The run configuration is unchanged.
